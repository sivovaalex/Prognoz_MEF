# Описание этапов разработки

Примечание: функционал реализуется строго по прототипу (блок «Пояснительная записка» внутри блока «Муниципальный прогноз», модуль «Прогноз СЭР МО»); данные ПЗ хранятся отдельно от данных подраздела «Показатели» и не влияют на них.

1.Создать хранилище данных пояснительной записки (ПЗ):
a.Создать сущность «Шаблон показателя ПЗ» со следующими полями:
●идентификатор;
●привязка к показателю общего дерева («Настройка показателей»); для ручного ввода — служебный идентификатор;
●раздел (направление) общего дерева;
●столбцы данных (наименования) — заполняются ОМСУ, подшапка со столбцами всегда видна в документе;
●строки (наименование, количество ячеек; по умолчанию = числу столбцов, минимум 1, максимум = число столбцов);
●отображаемое наименование в документе (для ручного ввода — введённое имя; для показателя из дерева — имя без префикса «Справочно:»);
●статус «активен/неактивен».
Примечание: неактивные шаблоны не участвуют в сборе.
b.Создать данные ОМСУ в разрезе «территория → шаблон»:
●значения ячеек (ключ ячейки = строка:подшапка:столбец);
●статус каждой ячейки (отсутствует = не заполнена);
●комментарий ЦИО при возврате ячейки;
●статус шаблона — выводится автоматически из статусов ячеек (ручное установление невозможно);
●время последнего изменения;
●лицо, отправившее ячейки на согласование.
c.Создать данные ЦИО в разрезе «шаблон → территория»: статус («не установлен» / «согласовано» / «возвращено»), время изменения.
d.Создать кампанию сбора ПЗ:
●статус («не запущен» / «идёт сбор» / «завершена»);
●дата и время запуска сбора;
●дата и время окончания сбора;
●срок заполнения ОМСУ (отображается в рабочем месте ОМСУ);
●срок согласования ЦИО (отображается в рабочем месте ЦИО);
●фактическое время запуска кампании.
e.Хранить отчётный год текущей кампании (2026) и данные архива (2025…2011) в виде снимков данных за завершённые кампании.

2.Реализовать статусы ячеек и правила:
a.Статусы ячейки:
●«черновик» — заполнена, не отправлена на согласование;
●«на согласовании у ЦИО»;
●«согласовано ЦИО» — изменение заблокировано;
●«возвращено на доработку».
b.Реализовать переходы статусов ячейки:
●ввод значения → «черновик»;
●«Отправить на согласование» → «на согласовании у ЦИО»;
●«Согласовать» (ЦИО) → «согласовано ЦИО»;
●«Вернуть» (ЦИО, с обязательным комментарием) → «возвращено на доработку»;
●«Отозвать согласование» (ЦИО) → «на согласовании у ЦИО»;
●«Отменить возврат» (ЦИО) → «на согласовании у ЦИО», комментарий удаляется;
●«Отозвать» (ОМСУ) → «черновик»;
●любое изменение значения отправленной/согласованной/возвращённой ячейки → «черновик», комментарий ЦИО удаляется.
c.Реализовать правила:
●пустое значение или «—» = ячейка не заполнена (статус и комментарий удаляются);
●пустую ячейку отправить невозможно;
●ячейки в статусах «на согласовании у ЦИО» и «согласовано ЦИО» заблокированы для ввода ОМСУ;
●возврат ЦИО без комментария невозможен.
d.Выводить статус шаблона автоматически из статусов ячеек:
●ячеек нет — «Не заполнена»;
●есть возвращённые — «Возвращена на доработку»;
●есть на согласовании у ЦИО — «На согласовании у ЦИО»;
●все заполненные ячейки согласованы — «Согласовано ЦИО»;
●иначе — «Черновик».
e.Реализовать правило ячеек строк: N ячеек строки равномерно занимают все данные столбцы.

3.Создать вкладку «Администрирование пояснительной записки» (доступ — пользователи с ролью «Администратор КФ»):
a.При открытии вкладки отображать заголовок «Администрирование пояснительной записки», подзаголовок «Шаблоны показателей пояснительной записки по разделам», кнопку «Добавить показатель» и таблицу шаблонов, сгруппированную по разделам общего дерева. Каждый раздел отображается строкой-заголовком с кнопкой «+» — при нажатии открывать модальное окно создания с выбранным разделом по умолчанию.
b.Реализовать строку шаблона со следующими колонками:
●№ — иерархический номер показателя из общего дерева (для ручного ввода — «—»);
●наименование показателя;
●столбцы — список названий столбцов;
●строки — список строк: «наименование — текст» или «наименование — текст (N ячеек)», без строк — «—»;
●статус — «Активен» / «Неактивен», неактивная строка затемнена;
●действия — кнопки «Редактировать» и «Активировать/Деактивировать».
c.Реализовать модальное окно «Новый показатель пояснительной записки» / «Редактирование показателя» с двухколоночным макетом: слева — настройки, справа — живой предпросмотр выходного документа (таблица в режиме «только чтение») по текущему черновику настроек.
В модальном окне реализовать:
■«Раздел показателя» — выпадающий список всех разделов общего дерева; при смене раздела сбрасывать выбранный показатель.
■«Наименование показателя» и переключатель:
●«Из общего дерева» — выпадающий список заполняемых (не групповых) показателей выбранного раздела; показатели, уже привязанные к другому шаблону, блокировать с пометкой «(уже добавлен)»;
●«Ввести вручную» — текстовое поле ввода наименования.
■«Конфигурация данных, заполняемых ОМСУ»:
●«Столбцы» — список полей «Название столбца» с кнопкой удаления и кнопкой «Добавить столбец»; при создании нового шаблона по умолчанию — «Отчёт», «Оценка», «Прогноз»;
●«Строки» — список строк: поле «Наименование строки», кнопка удаления, «Ячейки (ввод ОМСУ)» — чипы 1…N с кнопкой «×» (убрать ячейку) и кнопкой «+ Ячейка» (недоступна при достижении максимума = число столбцов); кнопка «Добавить строку»; при отсутствии строк — пояснение «Без строк — только строка показателя с подшапкой столбцов».
■Блок ошибок с текстом нарушенного правила валидации.
d.Реализовать валидацию при нажатии на «Сохранить»:
●«Выберите раздел»;
●«Введите наименование показателя» (ручной ввод);
●«Выберите показатель из общего дерева»;
●«Этот показатель уже добавлен в другой раздел»;
●«Заполните названия всех столбцов»;
●«Заполните названия всех строк».
e.Реализовать «Активировать/Деактивировать»: переключение статуса без подтверждения; неактивный шаблон исключается из сбора и выходных таблиц текущего года. Удаление шаблона не предусматривается.
f.Реализовать кнопки модального окна «Отмена» (закрыть без сохранения) и «Сохранить»; при редактировании статус активности сохранять без изменений.
g.Реализовать записи в журнал: «Добавлен показатель пояснительной записки», «Изменён показатель пояснительной записки».

4.Создать вкладку «Управление сбором» (доступ — пользователи с ролями «Администратор КФ» и «Куратор МЭФ»):
Примечание: макет вкладки идентичен вкладке «Управление» раздела «Показатели».
a.При открытии вкладки отображать заголовок «Управление сбором пояснительной записки», подзаголовок «Куратор отчёта: запуск сбора, контроль сроков» и карточку «Параметры сбора».
В карточке «Параметры сбора» реализовать:
■кнопку «Историчность сборов» в шапке карточки;
■поле «Дата запуска сбора» (дата и время);
■поле «Дата окончания сбора» (дата и время);
■кнопку «Сохранить даты»;
■при идущем сборе — кнопку «Остановить сбор» и бейдж «Сбор запущен {фактическое время запуска}»;
■при незапущенной кампании — кнопку «Запустить сбор»;
■текст «В указанную дату КФ автоматически рассылает уведомления и формы: {N} ОМСУ и {M} ЦИО», где N — число активных ОМСУ, M — число ЦИО.
b.Реализовать «Сохранить даты»: записывать дату и время запуска и окончания кампании; запись в журнал «Установлены даты сбора пояснительной записки (запуск: …, окончание: …)».
c.Реализовать «Запустить сбор» (доступно, когда кампания не запущена и не завершена):
■установить статус кампании «идёт сбор», зафиксировать время запуска;
■направить уведомление «Запущен сбор пояснительной записки» пользователям с ролями ОМСУ и ЦИО;
■запись в журнал «Запущен сбор пояснительной записки»;
■заменить кнопку на «Остановить сбор» и отобразить бейдж «Сбор запущен …».
d.Реализовать «Остановить сбор» (доступно только при идущем сборе): установить статус «не запущен»; запись в журнал «Сбор пояснительной записки остановлен».
e.При завершённой кампании кнопку «Запустить сбор» не отображать (завершённая кампания не перезапускается).
f.Реализовать модальное окно «Историчность сборов»: таблицу кампаний со следующими колонками:
■«Дата и время запуска»;
■«Период» — отчётный год кампании;
■«Статус» — «Завершён» / «В процессе»;
■«Инициатор».
Кнопка «Закрыть». История формируется из реальных кампаний.

5.Создать вкладку «Рабочее место ОМСУ (ПЗ)» (доступ — пользователи с ролью ОМСУ):
a.При открытии вкладки отображать заголовок «Пояснительная записка — {наименование территории}», подзаголовок «Заполнение показателей пояснительной записки · срок заполнения: {дата}» и таблицу ПЗ в режиме заполнения по форме выходного документа:
■шапка документа «Отчетный год: {текущий отчётный год}»;
■строки-заголовки разделов;
■строка «Наименование показателя | Данные муниципальных образований»;
■по каждому активному шаблону — строка показателя с подшапкой столбцов и строки данных с ячейками-текстовыми полями (многострочные, с возможностью изменения высоты).
b.Отображать только собственную территорию пользователя и только активные шаблоны.
c.Отображать ячейки в статусах «на согласовании у ЦИО» и «согласовано ЦИО» в режиме «только чтение»; под возвращённой ячейкой отображать текст «Возвращено ЦИО: {комментарий}».
d.Реализовать кнопки под ячейкой в зависимости от статуса ячейки:
■«Отправить» — статус «черновик»;
■«Отправить снова» — статус «возвращено на доработку»;
■«Отозвать» — статус «на согласовании у ЦИО»;
■метка «Согласовано» — статус «согласовано ЦИО» (кнопок нет).
e.Реализовать «Отправить на согласование»: отправлять только заполненные ячейки в статусах «черновик» / «возвращено на доработку» → «на согласовании у ЦИО»; фиксировать отправившее лицо и время; удалять комментарий ЦИО у отправленных ячеек; запись в журнал «Пояснительная записка: N яч. направлено на согласование ЦИО». Отправка выполняется прямым действием, без дополнительных диалогов.
f.Реализовать «Отозвать»: ячейки «на согласовании у ЦИО» → «черновик», отправившее лицо сбрасывается; запись в журнал «Пояснительная записка: N яч. отозвано с согласования».
g.Реализовать доработку возвращённой ячейки: при вводе значения статус «возвращено на доработку» → «черновик», далее повторная отправка кнопкой «Отправить снова».

6.Создать вкладку «Рабочее место ЦИО (ПЗ)» (доступ — пользователи с ролью отраслевого ЦИО):
a.При открытии вкладки отображать заголовок «Согласование пояснительной записки — {ЦИО (сокращённо)}», подзаголовок «{полное наименование ЦИО} · срок согласования: {дата}» и выпадающий список активных ОМСУ для выбора территории; при переключении перестраивать таблицу под выбранную территорию.
b.Отображать таблицу ПЗ в режиме согласования по форме выходного документа; ячейки, не отправленные ОМСУ (черновик), скрывать — отображать как «—».
c.Реализовать кнопки под ячейкой в зависимости от статуса ячейки:
■«Согласовать» и «Вернуть» — статус «на согласовании у ЦИО»;
■метка «Согласовано» и «Отозвать» — статус «согласовано ЦИО»;
■текст «Возвращено: {комментарий}» и «Отменить возврат» — статус «возвращено на доработку».
d.Реализовать модальное окно «Возврат ячейки ОМСУ на доработку» (открывается по «Вернуть»):
■поле «Комментарий для ОМСУ (обязательно)» (многострочное);
■кнопки «Отмена» и «Вернуть»; кнопка «Вернуть» заблокирована, пока комментарий не введён.
e.Реализовать «Согласовать»: ячейка → «согласовано ЦИО», комментарий (если был) удаляется; запись в журнал «Пояснительная записка: ячейка согласована».
f.Реализовать «Вернуть»: ячейка → «возвращено на доработку», комментарий из модального окна сохраняется; направить уведомление ОМСУ «Пояснительная записка: ячейка возвращена на доработку: {комментарий}»; запись в журнал — то же сообщение. Комментарий отображается у ОМСУ под ячейкой.
g.Реализовать «Отозвать согласование»: ячейка → «на согласовании у ЦИО»; запись в журнал «Пояснительная записка: согласование ячейки отозвано».
h.Реализовать «Отменить возврат»: ячейка → «на согласовании у ЦИО», комментарий удаляется; запись в журнал «Пояснительная записка: возврат ячейки отменён». Кнопка доступна, пока ОМСУ не отправил ячейку снова.
i.Ввод значений пользователем ЦИО не допускается.

7.Создать вкладку «Выходные таблицы пояснительной записки» (доступ — все пользователи):
a.При открытии вкладки отображать заголовок «Итоговые таблицы пояснительной записки» (для пользователей с ролью ОМСУ — «Итоговые таблицы пояснительной записки — {наименование территории}»), подзаголовок «Формирование итоговых таблиц по согласованным данным пояснительной записки» и таблицу в режиме «только чтение» по форме выходного документа:
■шапка «Отчетный год: {выбранный год}»;
■строки-заголовки разделов;
■строка «Наименование показателя | Данные муниципальных образований»;
■по каждому шаблону — строка показателя с подшапкой столбцов и строки данных со значениями; пустые ячейки — «—».
При отсутствии данных отображать «Нет данных для отображения».
b.Реализовать фильтры:
■«Территория» — список активных ОМСУ; для пользователей с ролью ОМСУ фильтр скрыт — территория фиксированно собственная;
■«Отчетный год» — «{текущий год} (текущий)» и «{год} (архив)» за каждый архивный год (2025…2011); при переключении перестраивать таблицу;
■«Показатели» — «Все показатели» и наименования активных шаблонов; доступен только для текущего года, для архива скрыт.
c.Для текущего отчётного года отображать только активные шаблоны с живыми данными; для архивного года — все шаблоны (включая неактивные) по снимку данных на момент завершения кампании.
d.При смене отчётного года выбранный показатель, отсутствующий в списке нового года, сбрасывать в «Все показатели».

8.Реализовать уведомления и журнал истории:
a.Реализовать уведомления через центр уведомлений системы:
■при запуске сбора — пользователям с ролями ОМСУ и ЦИО: «Запущен сбор пояснительной записки»;
■при возврате ячейки ЦИО — пользователю ОМСУ: «Пояснительная записка: ячейка возвращена на доработку: {комментарий}».
b.Реализовать записи в журнал истории (аудит):
■«Добавлен показатель пояснительной записки» / «Изменён показатель пояснительной записки» — инициатор: Администратор;
■«Установлены даты сбора пояснительной записки (запуск: …, окончание: …)» / «Запущен сбор пояснительной записки» / «Сбор пояснительной записки остановлен» — инициатор: Куратор МЭФ;
■«Пояснительная записка: N яч. направлено на согласование ЦИО» / «Пояснительная записка: N яч. отозвано с согласования» — инициатор: ОМСУ;
■«Пояснительная записка: ячейка согласована» / «Пояснительная записка: ячейка возвращена на доработку: {комментарий}» / «Пояснительная записка: согласование ячейки отозвано» / «Пояснительная записка: возврат ячейки отменён» — инициатор: ЦИО.

9.Реализовать интеграцию с существующей системой:
a.Разделы и показатели брать из справочника «Настройка показателей»; привязка показателя к шаблону ПЗ — одна на показателя (повторная блокируется); групповые строки дерева в выбор не попадают.
b.Отображение подраздела «Пояснительная записка» в блоке «Муниципальный прогноз» управлять флагом блока.
c.Доступ к вкладкам «Рабочее место ОМСУ (ПЗ)» и «Рабочее место ЦИО (ПЗ)» фильтровать по назначенным согласующим блока.
d.Активные ОМСУ и ЦИО брать из справочника территорий (для счётчиков в примечании «Управление сбором» и списков выбора/фильтров).

10.Критерии приёмки:
a.Администратор создаёт шаблон из дерева и вручную, редактирует, деактивирует; предпросмотр совпадает с выходным документом.
b.Куратор устанавливает даты, запускает сбор (уведомления ОМСУ/ЦИО), останавливает; история сборов отражает кампании.
c.ОМСУ заполняет ячейки, отправляет на согласование, отзывает; пустые ячейки отправить нельзя; заблокированные ячейки не редактируются.
d.ЦИО видит только отправленные ячейки, согласовывает, возвращает с обязательным комментарием (уведомление ОМСУ), отзывает согласование, отменяет возврат.
e.Выходные таблицы: текущий год — активные шаблоны с фильтрами; архив — снимки без фильтра показателя; ОМСУ видит только свою территорию.
f.Статусы шаблонов выводятся автоматически и совпадают с правилами п. 2.
